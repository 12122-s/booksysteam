# 虚拟机部署说明（Java 版）

服务器上已经跑着 Python 版？没关系 —— Java 版就是为"无缝替换"设计的。
两种部署方式，先选一种：

| 方式 | MySQL 库名 | 适用场景 |
| --- | --- | --- |
| **方式一：替换上线（推荐）** | 不改，直连老库 `library_system` | Java 版接管 Python 版，读者数据、密码全部保留 |
| **方式二：并行试用** | 改成新库，如 `library_java` | 两套同时跑、数据各自独立，试用满意再切换 |

---

## 一、先回答：MySQL 库名要不要改？

- **不需要为兼容性改名。** 两个版本的表结构、密码哈希（werkzeug 的 scrypt/pbkdf2）、
  备份 .sql 格式完全互通 —— Java 版直连 Python 版的库，什么都不用迁移。
- **只有"并行独立数据"才需要改库名**：给 Java 版设环境变量
  `LIB_DB_NAME=library_java`，首次启动会自动建库、建表、写入默认设置
  （管理员 admin / 123456），空库起步。想带上老数据，用 Python 版导出的
  .sql 备份在 Java 版「系统设置 → 数据备份 → 恢复」导入即可。

> ⚠️ **共用同一个库时的注意事项**：两套系统都会跑「到期提醒邮件」和「每日备份」
> 定时任务。同时运行会重复发邮件、重复备份。所以要么停掉 Python 版，
> 要么在其中一边的「系统设置」里关闭「到期提醒」和「每日自动备份」开关。

## 二、打包（本地 Windows 上做）

```bat
cd /d D:\IdeaProjects\booksysteam
mvnw.cmd package -DskipTests
```

产物：`target\booksysteam-1.0.0.jar`（约 50MB 的可执行 fat jar，
自带 Tomcat，不需要装 Tomcat）。

> 你的机器 PATH 里 Oracle 的 `javapath\java` shim 可能已损坏（执行 java 无反应）。
> 如果 `mvnw` 报错，先设 `set JAVA_HOME=C:\Program Files\Zulu\zulu-17` 再执行。

---

## 三、上传到虚拟机

```bash
# 在虚拟机上建个独立目录（和 Python 版分开，互不干扰）
ssh 用户名@虚拟机IP "mkdir -p ~/library-java/target"

# 上传 jar（注意进 target/ 子目录，Dockerfile 从这里取）
scp target/booksysteam-1.0.0.jar 用户名@虚拟机IP:~/library-java/target/
```

虚拟机需要 JDK 17+。没有的话（Ubuntu/Debian）：

```bash
sudo apt update && sudo apt install -y openjdk-17-jre-headless
# CentOS/RHEL: sudo yum install -y java-17-openjdk java-17-openjdk-devel
```

## 四、运行

### 方式一：替换上线（连老库，不改库名）

```bash
cd ~/library-java
LIB_DB_HOST=127.0.0.1 \
LIB_DB_PORT=3306 \
LIB_DB_USER=root \
LIB_DB_PASSWORD=你的密码 \
LIB_DB_NAME=library_system \
SERVER_PORT=8081 \
nohup java -jar booksysteam-1.0.0.jar > app.log 2>&1 &
```

> `SERVER_PORT=8081`：Python 版占着 8080 时，Java 版先用 8081。
> 确认没问题、停掉 Python 版后，可以把 Java 版改回 8080。

### 方式二：并行试用（新库，数据独立）

推荐直接用 **Docker**（虚拟机装好 Docker 即可，与应用怎么跑互不干扰）。
需要上传 3 个文件到服务器 `~/library-java/`：`target/booksysteam-1.0.0.jar`
（传到其下的 target/ 子目录）、`Dockerfile`、`docker-compose.yml`，然后在服务器上：

```bash
# 虚拟机没有 Docker 的话先装（Ubuntu/Debian）：
# curl -fsSL https://get.docker.com | sh

cd ~/library-java
nano docker-compose.yml        # 把 LIB_DB_PASSWORD 改成虚拟机 MySQL 的密码
docker compose up -d --build
docker logs -f library-java    # 看启动日志
```

说明：

- 独立新库 `library_java`，端口 `8081`，服务器上 Python 版（8080 / `library_system`）完全不受影响；
- `network_mode: host` 让容器直连宿主机的 MySQL（127.0.0.1:3306），不用给 MySQL 开远程账号；
- 封面上传（`uploads/`）和每日备份（`backups/`）挂载在宿主机 `~/library-java/` 下，容器重建不丢；
- 首次启动自动建库建表，浏览器登录 admin / 123456。

**想把服务器上 Python 版的真实数据拷一份过来试用**：登录 Python 版
「系统设置 → 导出完整备份」下载 .sql，再登录 Java 版（8081）
「系统设置 → 恢复」上传导入即可 —— 两个版本的备份格式互通。

不想用 Docker 的话，服务器上也可以直接跑：改好 `start.sh` 里的
`DB_PASSWORD` 后 `bash start.sh` 启动、`bash start.sh stop` 停止
（这个脚本也要一并上传到 ~/library-java/），效果相同。

### 让它常驻：注册 systemd 服务（推荐，开机自启 + 崩了自动拉起）

```bash
sudo tee /etc/systemd/system/library-java.service > /dev/null << 'EOF'
[Unit]
Description=Library Management System (Java)
After=network.target mysql.service

[Service]
User=你的用户名
WorkingDirectory=/home/你的用户名/library-java
Environment=LIB_DB_HOST=127.0.0.1
Environment=LIB_DB_PORT=3306
Environment=LIB_DB_USER=root
Environment=LIB_DB_PASSWORD=你的密码
Environment=LIB_DB_NAME=library_system
Environment=SERVER_PORT=8081
ExecStart=/usr/bin/java -jar /home/你的用户名/library-java/booksysteam-1.0.0.jar
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now library-java
sudo systemctl status library-java      # 看运行状态
journalctl -u library-java -f           # 看实时日志
```

（把上面两处 `你的用户名` 和密码换成实际值。`WorkingDirectory` 很重要 ——
封面/收款码上传目录 `uploads/` 和自动备份目录 `backups/` 都建在这里。）

## 五、验证

```bash
curl http://127.0.0.1:8081/health        # 返回 ok 即正常
```

浏览器打开 `http://虚拟机IP:8081`：

- 管理员：`admin` / 初始密码 `123456`（新库时；连老库则用你原来的管理密码）
- 登录后先检查「系统设置」里的借期、罚金等规则

**替换上线的切换步骤**：Java 版（8081）连老库试用几天 → 没问题后
`sudo systemctl stop` 掉 Python 版服务 → Java 版改 `SERVER_PORT=8080`
重启 → 完成。整个过程数据零迁移。

## 六、nginx 反向代理（可选，对外用 80 端口时）

```nginx
server {
    listen 80;
    server_name 你的域名或IP;

    location / {
        proxy_pass http://127.0.0.1:8081;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_read_timeout 60s;
    }
}
```

改完 `sudo nginx -s reload`。Java 版会把 `X-Forwarded-For` 记进操作日志。

## 七、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 启动报 `Access denied` | `LIB_DB_USER/PASSWORD` 不对；或 MySQL 只允许本机登录 |
| 启动报 `Communications link failure` | MySQL 没启动，或 `LIB_DB_HOST/PORT` 不对 |
| 读者说老密码登不上 | 不会发生 —— Python 版的密码哈希 Java 版能直接校验（有单元测试）。真遇到就用管理员「重置密码」 |
| 两个系统都发提醒邮件 | 共用库的两套系统定时任务重复，关掉一边的「到期提醒」开关 |
| 封面上传失败 | `uploads/` 目录权限不足：`chown -R 你的用户名 ~/library-java` |
| 想迁移到新机器 | 下载「系统设置 → 导出完整备份.sql」，在新机器恢复即可（跨 Python/Java 版都行） |

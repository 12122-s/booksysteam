# 服务器部署说明（Java 版）

面向 Linux 服务器（虚拟机 / 云主机）的部署指南，两种方式任选：

| 方式 | 依赖 | 适用场景 |
| --- | --- | --- |
| **方式一：Docker Compose（推荐）** | 只要装好 Docker | 自带 MySQL 容器，一条命令起停，环境隔离干净 |
| **方式二：裸机 jar + systemd** | 装好 JDK 17 和 MySQL 8 | 不想引入 Docker，或要复用服务器上已有的 MySQL |

两种方式都用同一份 `target/booksysteam-1.0.0.jar`，改的只是跑法。

---

## 一、打包（在本地开发机上做）

```bat
cd /d D:\IdeaProjects\booksysteam
mvnw.cmd package -DskipTests
```

产物：`target\booksysteam-1.0.0.jar`（约 50MB 的可执行 fat jar，自带 Tomcat，
服务器上**不需要另装 Tomcat**）。

> 本机 PATH 里 Oracle 的 `javapath\java` shim 已损坏（执行 `java` 无任何输出）。
> 如果 `mvnw` 报错，先设好 JAVA_HOME 再执行：
> `set JAVA_HOME=C:\Program Files\Zulu\zulu-17`

## 二、方式一：Docker Compose（推荐）

`docker-compose.yml` **自带一个独立的 MySQL 8 容器**，数据落在宿主机 `./dbdata`，
和应用一起编排，不用去配服务器的 MySQL。

### 1. 上传文件

```bash
ssh 用户名@服务器IP "mkdir -p ~/library-java/target"

# jar 要放进 target/ 子目录（Dockerfile 从这里 COPY）
scp target/booksysteam-1.0.0.jar 用户名@服务器IP:~/library-java/target/
scp Dockerfile docker-compose.yml .env.example 用户名@服务器IP:~/library-java/
```

### 2. 启动

```bash
# 服务器没有 Docker 的话先装（Ubuntu/Debian）：
# curl -fsSL https://get.docker.com | sh

cd ~/library-java
cp .env.example .env                   # 可选：想改默认密码就在这里改
docker compose up -d --build
docker compose logs -f library-java    # 看启动日志
```

浏览器打开 `http://服务器IP:8081`，管理员 `admin` / 初始密码 `123456`。

### 3. 说明

- **数据隔离**：MySQL 跑在独立容器里，数据存宿主机 `./dbdata`，
  和服务器上已有的 MySQL（比如宝塔面板那套）完全无关 —— 不需要给它开远程账号，
  也不用把它的 root 密码填进来；
- **最小权限**：应用连库用的是专用账号 `library_java`（只对 `library_java` 这一个库有权限），不是 root；
- **启动顺序**：`depends_on` 配了 `condition: service_healthy`，等 MySQL 健康检查通过应用才启动，
  不会出现「启动即报连不上数据库、然后靠 restart 反复重启」；
- **持久化**：封面上传（`./uploads`）和每日备份（`./backups`）挂在宿主机 `~/library-java/` 下，
  容器重建不丢数据；
- **端口**：宿主机 `8081` → 容器 `8081`（`SERVER_PORT` 决定）；
- **停止**：`docker compose down`（数据保留在 `./dbdata`；加 `-v` 才会连数据卷一起删）。

> ⚠️ MySQL 的账号密码**只在数据目录第一次初始化时生效**。如果 `./dbdata` 已经存在，
> 之后改 `.env` 里的密码不会生效 —— 要么进容器手动改账号，要么删掉 `./dbdata`
> 重新初始化（会清空数据）。

### 4. 把数据迁到新机器

「系统设置 → 导出完整备份」下载 `.sql`，在新部署的实例里「系统设置 → 恢复」上传导入即可。

## 三、方式二：裸机 jar + systemd

想复用服务器上已有的 MySQL，或者不想装 Docker，就用这种方式。

### 1. 装 JDK 17

```bash
sudo apt update && sudo apt install -y openjdk-17-jre-headless
# CentOS/RHEL: sudo yum install -y java-17-openjdk java-17-openjdk-devel
java -version        # 确认是 17+
```

MySQL 8 如果还没装：

```bash
sudo apt install -y mysql-server
sudo mysql -e "CREATE DATABASE library_system CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;"
```

### 2. 上传

```bash
ssh 用户名@服务器IP "mkdir -p ~/library-java"
scp target/booksysteam-1.0.0.jar 用户名@服务器IP:~/library-java/
```

### 3. 先手动跑一次确认能用

```bash
cd ~/library-java
LIB_DB_HOST=127.0.0.1 \
LIB_DB_PORT=3306 \
LIB_DB_USER=root \
LIB_DB_PASSWORD=你的密码 \
LIB_DB_NAME=library_system \
SERVER_PORT=8081 \
nohup java -jar booksysteam-1.0.0.jar > app.log 2>&1 &
```

首次启动会自动建库建表并写入默认设置（管理员 `admin` / `123456`），
不需要手动执行任何 SQL。

也提供了脚本版本：改好 `deploy/start.sh` 里的 `DB_PASSWORD` 后
`bash start.sh` 启动、`bash start.sh stop` 停止。

### 4. 注册 systemd 服务（推荐，开机自启 + 崩了自动拉起）

```bash
sudo tee /etc/systemd/system/library-java.service > /dev/null << 'EOF'
[Unit]
Description=Library Management System (Java)
After=network.target mysql.service

[Service]
User=你的用户名
WorkingDirectory=/home/你的用户名/library-java
Environment=LIB_DB_HOST=127.0.0.1
Environment=LIB_DB_PORT=3306
Environment=LIB_DB_USER=root
Environment=LIB_DB_PASSWORD=你的密码
Environment=LIB_DB_NAME=library_system
Environment=SERVER_PORT=8080
ExecStart=/usr/bin/java -jar /home/你的用户名/library-java/booksysteam-1.0.0.jar
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now library-java
sudo systemctl status library-java      # 看运行状态
journalctl -u library-java -f           # 看实时日志
```

> 把上面两处 `你的用户名` 和密码换成实际值。`WorkingDirectory` 很重要 ——
> 封面上传目录 `uploads/` 和自动备份目录 `backups/` 都建在这里
> （它们固定在**进程工作目录**下，不跟着 jar 走）。

> ⚠️ 定时任务（到期提醒、每日备份）跟进程绑定，**同一套数据库只能跑一个实例**，
> 否则会重复发提醒邮件、重复备份。

## 四、nginx 反向代理（可选，对外用 80 端口时）

```nginx
server {
    listen 80;
    server_name 你的域名或IP;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_read_timeout 60s;
    }
}
```

改完 `sudo nginx -s reload`。应用会把 `X-Forwarded-For` 记进操作日志。

> 上了 HTTPS 的话，证书用 `certbot --nginx` 一条命令就能配好。

## 五、验证

```bash
curl http://127.0.0.1:8080/health        # 返回 ok 即正常
curl http://127.0.0.1:8080/api/v1/books  # 应返回 401（未带 token），说明 API 起来了
```

浏览器打开 `http://服务器IP:8080`（Docker 方式是 8081）：

- 管理员：`admin` / 初始密码 `123456`
- **登录后第一件事**：改管理员密码，并检查「系统设置」里的借期、罚金等规则

## 六、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 启动报 `Access denied` | `LIB_DB_USER/PASSWORD` 不对；或 MySQL 只允许本机登录 |
| 启动报 `Communications link failure` | MySQL 没启动，或 `LIB_DB_HOST/PORT` 不对 |
| Docker 方式应用反复重启 | 先看 `docker compose logs library-db`，多半是 MySQL 还没初始化完或 `./dbdata` 权限不对 |
| 封面上传失败 | `uploads/` 目录权限不足：`chown -R 你的用户名 ~/library-java` |
| 登录后一直跳回登录页 | 系统重启会让所有会话失效（启动戳机制），重新登录即可 |
| 提醒邮件发重复了 | 同一套库跑了多个实例，只保留一个，或在「系统设置」里关掉「到期提醒」 |
| 忘记管理员密码 | 用 `admin` 邮箱走「忘记密码」流程（需先配好 SMTP），或直接改数据库里的密码哈希 |
| 想迁移到新机器 | 下载「系统设置 → 导出完整备份.sql」，在新机器恢复即可 |
